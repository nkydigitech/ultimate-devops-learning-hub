# Your IP Address and Hostname

Every computer has an address and a name:

<Terminal
  command="hostname && hostname -I"
  output={`devops-hub
172.28.192.1`}
/>

- `hostname` — the computer's name
- `hostname -I` — its IP address on the network

---

# Network Interfaces

<CommandBlock command={`ip addr    # show all network interfaces
ip a       # short form of the same command`} />

Common interfaces you'll see:

| Interface | Meaning |
|-----------|---------|
| `lo` | Loopback (the machine talking to itself) |
| `eth0` | Wired Ethernet |
| `wlan0` | Wireless |

---

# Testing Connectivity

Ping tests whether you can reach another machine. Stop it with **Ctrl + C**.

<Terminal
  command="ping 8.8.8.8"
  output={`64 bytes from 8.8.8.8: icmp_seq=1 ttl=115 time=12.4 ms
64 bytes from 8.8.8.8: icmp_seq=2 ttl=115 time=11.9 ms`}
/>

Then test a **domain name** — if this works, DNS is resolving correctly:

<CommandBlock command="ping google.com" />

---

# Routing and Open Ports

<CommandBlock command={`ip route     # where does traffic go? shows the default gateway
ss -tuln     # which ports are listening on this machine?`} />

<Terminal
  command="ip route"
  output="default via 192.168.1.1 dev eth0"
/>

The routing table tells Linux where to send network traffic; `ss -tuln` is invaluable for checking whether your application is actually listening.

# Downloading from the Network

<CommandBlock command={`curl https://example.com     # fetch a URL and print it
wget https://example.com     # download a file`} />

These commands appear constantly in automation scripts.

# Real DevOps Example

A deployment fails because the server can't reach GitHub. The very first check:

<Terminal
  command="ping github.com"
  output={`ping: github.com: Temporary failure in name resolution`}
/>

That error points straight at **DNS** — if networking is broken, nothing else matters.

# ⚠ Common Beginner Mistakes

<Warning title="Ping the IP, then the name">
If `ping 8.8.8.8` works but `ping google.com` fails, your connectivity is fine but **DNS** is misconfigured. Testing an IP and a domain separately instantly narrows down the problem.
</Warning>

# 💼 Interview Preparation

<InterviewPrep question="Walk me through how you'd troubleshoot 'the server can't reach the internet'.">
  A structured, layer-by-layer approach:

  1. **Interface up?** `ip addr` — confirm the interface has an IP.
  2. **Gateway reachable?** `ip route` to find the default gateway, then `ping` it.
  3. **Internet reachable?** `ping 8.8.8.8` — tests raw connectivity by IP.
  4. **DNS working?** `ping google.com` — if the IP works but the name doesn't, it's DNS (check `/etc/resolv.conf`).
  5. **Application layer?** `curl -v https://...` and `ss -tuln` to confirm ports and services.

  Working from the lowest layer up quickly isolates where the break is.
</InterviewPrep>
