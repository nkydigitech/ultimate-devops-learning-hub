One of the biggest differences between Windows and Linux is how files are organized. Windows uses drive letters like `C:\` and `D:\`. Linux has no drive letters — **everything grows from a single root directory** called `/`. Think of it as the top of a giant tree.

# The Linux Directory Tree

Every Linux system — Ubuntu, Debian, CentOS, Amazon Linux — follows this structure:

<CommandBlock command={`/
├── bin     # essential commands (ls, cp, mv)
├── boot    # boot loader files
├── dev     # device files
├── etc     # configuration files
├── home    # user home directories
├── lib     # shared libraries
├── opt     # optional / third-party software
├── proc    # kernel & process info (virtual)
├── root    # the root user's home
├── tmp     # temporary files
├── usr     # installed software
└── var     # logs and changing data`} language="text" />

---

# The Directories That Matter Most

| Directory | Purpose |
|-----------|---------|
| `/` | The root — everything starts here |
| `/home` | Personal user folders (`/home/student`) |
| `/etc` | Configuration files (`/etc/hosts`, `/etc/passwd`) |
| `/var` | Changing data — logs, cache, databases (`/var/log`) |
| `/tmp` | Temporary files (may be auto-cleaned) |
| `/usr` | Installed software and applications |
| `/bin` | Essential commands like `ls`, `cp`, `cat` |
| `/root` | The **root user's** home — *not* the same as `/` |

<Warning title="/ is not /root">
`/` is the top of the entire filesystem. `/root` is just the home directory of the root (admin) user. They look similar but are completely different places.
</Warning>

# Moving Around the Tree

<CommandBlock command={`cd            # go to your home directory
cd /          # go to the root directory
cd /var/log   # jump to the log directory
ls /etc       # list configuration files
ls ~          # list your home folder`} />

# Real DevOps Example

When a web server stops working, a DevOps engineer usually starts by reading the logs:

<Terminal
  command="cd /var/log && ls && tail syslog"
  output={`auth.log  dpkg.log  nginx  syslog
Jul 12 10:31:02 web01 systemd[1]: Started Daily apt upgrade.
Jul 12 10:31:05 web01 nginx[812]: signal process started`}
/>

Many production problems are diagnosed simply by reading `/var/log`.

# 💼 Interview Preparation

<InterviewPrep question="What is the Filesystem Hierarchy Standard (FHS) and why does it matter?">
  The **FHS** is a standard that defines the directory structure and the purpose of each directory on Linux systems.

  It matters because it means a script or engineer can rely on configuration being in `/etc`, logs in `/var/log`, and binaries in `/bin` or `/usr/bin` — regardless of which distribution is running. This consistency is what makes automation and troubleshooting portable across servers.
</InterviewPrep>
