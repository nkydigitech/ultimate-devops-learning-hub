# What is Bash?

Bash stands for **Bourne Again SHell**. A shell is a program that lets you communicate with Linux — instead of clicking buttons, you type commands.

<CommandBlock command={`You
 ↓
Bash (the shell)
 ↓
Linux Kernel
 ↓
Computer`} language="text" />

Almost every DevOps automation begins with Bash.

# Your First Command and Variables

<Terminal command={'echo "Hello Linux!"'} output="Hello Linux!" />

Variables store information. The `$` tells Bash to use the value stored inside:

<CommandBlock command={`name="John"
echo $name        # John

echo $HOME        # /home/student  (built-in)
echo $USER        # student         (built-in)`} />

---

# Creating Your First Script

Create a file, open it in an editor, and add a shebang plus a command:

<CommandBlock command={`nano hello.sh`} />

<CommandBlock command={`#!/bin/bash

echo "Welcome to DevOps!"`} />

Save it, make it executable, and run it:

<Terminal
  command="chmod +x hello.sh && ./hello.sh"
  output="Welcome to DevOps!"
/>

Congratulations — you've written your first Bash program.

<Warning title="Two things beginners forget">
- The **shebang** `#!/bin/bash` on line 1 — it tells Linux how to run the file.
- The **execute permission** — if you see `Permission denied`, run `chmod +x filename.sh`.
</Warning>

---

# Reading User Input

<CommandBlock command={`#!/bin/bash

echo "What is your name?"
read username
echo "Welcome $username!"`} />

Anything after `#` is a **comment** and is ignored by Bash — use comments to explain your code.

---

# Real DevOps Example

Instead of typing three deploy commands every day, put them in a script and run it with one command:

<CommandBlock command={`#!/bin/bash
# deploy.sh — build and ship the app

git pull
docker build -t app .
docker compose up -d`} />

<Terminal command="./deploy.sh" output={`Already up to date.
Successfully built app
Container app-1 Started`} />

Automation saves time and removes human error.

# 💼 Interview Preparation

<InterviewPrep question="What is a shebang, and what happens if you omit it?">
  A **shebang** is the `#!/bin/bash` (or `#!/usr/bin/env bash`) line at the very top of a script. It tells the operating system which interpreter to use when the file is executed directly.

  If you omit it and run `./script.sh`, the system may fall back to whatever the current shell is, which can behave differently (for example `sh` vs `bash`). Being explicit with a shebang makes scripts portable and predictable — which matters a lot in CI/CD pipelines.
</InterviewPrep>
