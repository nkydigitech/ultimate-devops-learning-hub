# Azure vs AWS — Same Ideas, Different Names

The cloud concepts you learned for AWS transfer directly. Only the names change:

| Concept | AWS | Azure |
|---------|-----|-------|
| Virtual server | EC2 | Virtual Machine (VM) |
| Object storage | S3 | Blob Storage |
| Identity & access | IAM | Microsoft Entra ID + RBAC |
| Networking | VPC | Virtual Network (VNet) |
| Managed database | RDS | Azure SQL Database |
| Serverless functions | Lambda | Azure Functions |

<Tip title="You already know the concepts">
If you understood the AWS section, you already understand 80% of Azure. Focus on learning the naming and the console — the underlying ideas (compute, storage, identity, networking) are the same.
</Tip>

# The Azure Hierarchy

Azure organises everything in a clear hierarchy:

<CommandBlock command={`Management Group        (optional, groups subscriptions)
└── Subscription        (billing + access boundary)
    └── Resource Group  (a folder for related resources)
        ├── Virtual Machine
        ├── Storage Account
        └── Virtual Network`} language="text" />

This structure — especially the **Resource Group** — is one of Azure's nicest features, and it's the focus of the next lesson.

# 💼 Interview Preparation

<InterviewPrep question="Why might a company choose Azure over AWS?">
  Several common reasons:

  - **Existing Microsoft investment:** organisations already using Windows Server, Active Directory, SQL Server, and Microsoft 365 get tight integration and often favourable licensing.
  - **Hybrid cloud:** Azure Arc and Azure Stack are strong for companies that need to run workloads across on-premises and cloud.
  - **Enterprise agreements:** many large enterprises already have Microsoft enterprise agreements, making Azure procurement simpler.
  - **Compliance:** Azure has broad compliance certifications valued in regulated industries.

  In practice the technical capabilities of AWS and Azure are broadly comparable — the choice is often driven by existing relationships, skills, and cost agreements rather than raw features.
</InterviewPrep>
