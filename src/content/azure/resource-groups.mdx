A **Resource Group** is a container that holds related Azure resources — a VM, its disk, its network, its IP — so you can manage them as one unit. It's one of Azure's most practical ideas and has no exact single equivalent in AWS.

---

# 🎯 Learning Objectives

By the end of this lesson you will:

- Understand what a resource group is and why it's useful
- Create and delete resource groups with the CLI
- Apply tags for organization and cost tracking
- Understand the lifecycle benefit of grouping resources

---

# Why Resource Groups Matter

Everything in Azure lives inside a resource group. Grouping gives you:

- **Lifecycle management** — deploy or delete an entire application's resources together.
- **Access control** — apply permissions (RBAC) at the group level.
- **Cost visibility** — see spend per group, often per project or environment.
- **Organization** — a clear place for everything, e.g. `rg-shop-prod`, `rg-shop-dev`.

<Tip title="A common pattern">
Teams often create one resource group **per application per environment** — `rg-webapp-dev`, `rg-webapp-prod`. When a project ends, deleting the group cleans up everything in one move.
</Tip>

# Create a Resource Group

<CommandBlock command={`az group create \\
  --name rg-devops-lab \\
  --location westeurope`} />

<Terminal
  command="az group list --output table"
  output={`Name            Location    Status
--------------  ----------  ---------
rg-devops-lab   westeurope  Succeeded`}
/>

---

# Tag Resources for Cost Tracking

Tags are key/value labels that make billing and organization far easier:

<CommandBlock command={`az group update --name rg-devops-lab \\
  --set tags.environment=dev tags.project=learning-hub`} />

---

# Clean Up in One Command

This is the real payoff. Deleting a resource group deletes **everything inside it**:

<CommandBlock command={`az group delete --name rg-devops-lab --yes --no-wait`} />

<Warning title="Deletion is permanent and recursive">
`az group delete` removes every resource in the group — VMs, disks, networks, data. There's no undo. Double-check the group name, especially before running it against anything that might be production.
</Warning>

# 💼 Interview Preparation

<InterviewPrep question="How do Azure resource groups help with cost management and cleanup?">
  Resource groups act as a lifecycle and organizational boundary:

  - **Cleanup:** because every resource belongs to a group, deleting the group removes all associated resources in one operation — no orphaned disks or IPs quietly generating charges.
  - **Cost allocation:** combined with **tags**, you can report spend per group, per project, or per environment, making it clear who is spending what.
  - **Consistency:** grouping resources per environment (dev/test/prod) keeps environments cleanly separated and easy to spin up or tear down, which is ideal for CI/CD and short-lived test environments.

  This is a big practical advantage over scattering resources with no container.
</InterviewPrep>
