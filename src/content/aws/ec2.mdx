**EC2 (Elastic Compute Cloud)** gives you virtual servers — "instances" — that you can launch in minutes and shut down when you're done. It's the service you'll use to run applications, host websites, and practise everything you learned in the Linux section, in the cloud.

# Anatomy of an EC2 Instance

When you launch an instance you choose:

| Choice | What it means |
|--------|---------------|
| **AMI** | The base image — the OS and pre-installed software (e.g. Ubuntu 24.04) |
| **Instance type** | The size — vCPUs and memory (e.g. `t3.micro`) |
| **Key pair** | The SSH key you'll use to log in |
| **Security group** | A virtual firewall controlling inbound/outbound traffic |
| **Storage (EBS)** | The virtual hard disk attached to the instance |

<Tip title="Free-tier friendly">
The `t2.micro` / `t3.micro` instance types are included in the AWS Free Tier for a set number of hours per month — perfect for practising without a bill.
</Tip>

---

# Security Groups = Firewalls

A security group controls what traffic can reach your instance. A typical web server:

<CommandBlock command={`Inbound rules
─────────────
SSH   (port 22)   ← your IP only        # you can log in
HTTP  (port 80)   ← 0.0.0.0/0           # anyone can browse
HTTPS (port 443)  ← 0.0.0.0/0`} language="text" />

<Warning title="Don't open SSH to the world">
Setting SSH (port 22) to `0.0.0.0/0` exposes your login to the entire internet and invites constant brute-force attempts. Restrict port 22 to **your IP address** only.
</Warning>

# Connect with SSH

Remember SSH from the Linux section? This is where it pays off. Use the key pair you selected at launch:

<CommandBlock command={`chmod 400 my-key.pem
ssh -i my-key.pem ubuntu@<instance-public-ip>`} />

<Terminal
  command="ssh -i my-key.pem ubuntu@54.72.10.5"
  output={`Welcome to Ubuntu 24.04 LTS (GNU/Linux 6.8.0-aws x86_64)
ubuntu@ip-172-31-8-14:~$`}
/>

You're now inside a Linux server running in an AWS data centre.

# Control the Cost

<CommandBlock command={`# From the CLI (or the console):
aws ec2 stop-instances  --instance-ids i-0abc123   # stop = no compute charge
aws ec2 start-instances --instance-ids i-0abc123   # start it again later
aws ec2 terminate-instances --instance-ids i-0abc123  # delete permanently`} />

<Warning title="Stop or terminate when you're done">
A running instance is billed by the second. **Stop** it to pause compute charges, or **terminate** it to remove it entirely. Forgetting a running instance is the classic "surprise AWS bill".
</Warning>

# 💼 Interview Preparation

<InterviewPrep question="What's the difference between stopping and terminating an EC2 instance?">
  - **Stopping** shuts the instance down like powering off a computer. You stop paying for compute, the attached EBS volume (and its data) is preserved, but the public IP usually changes on restart. You can start it again later.

  - **Terminating** permanently deletes the instance. By default the root EBS volume is deleted too, so the data is gone. You cannot restart a terminated instance.

  Rule of thumb: **stop** when you'll come back to it; **terminate** when you're truly done and want to stop all associated charges.
</InterviewPrep>
