A chatbot answers your question. An **AI agent** takes a goal, decides on the steps, uses tools to carry them out, and checks its own progress until the goal is done. That shift — from *answering* to *acting* — is what "agentic AI" means, and it's rapidly changing how DevOps and engineering teams work.

# LLMs in One Minute

A **large language model** is a system trained on vast amounts of text to predict and generate language. Given some input (a **prompt**), it produces a useful response. Modern LLMs can write code, summarise logs, explain errors, and follow instructions.

<Tip title="The mental model">
Think of an LLM as an extremely well-read assistant that reasons in text. It doesn't "know" live facts about your systems unless you *give* it that context — which is exactly what agents and tools do.
</Tip>

---

# Chatbot vs Agent

| | **Chatbot** | **Agent** |
|---|-------------|-----------|
| Input | A question | A goal |
| Output | An answer | Completed actions |
| Tools | None | Can call tools/APIs |
| Steps | One turn | Many steps, looping |
| Example | "How do I restart a pod?" | "Find and restart the crashing pods" |

The agent doesn't just *tell* you what to do — given the right tools and permissions, it can *do* it.

---

# The Agent Loop

An agent works in a cycle until the goal is met:

<CommandBlock command={`         ┌──────────────────────────────┐
         ▼                              │
   1. REASON  →  2. ACT  →  3. OBSERVE ─┘
   (plan next   (use a       (read the
    step)        tool)        result)`} language="text" />

1. **Reason** — decide the next step toward the goal.
2. **Act** — call a tool (run a command, query an API, read a file).
3. **Observe** — take in the result and update the plan.

It repeats this loop, adapting as it goes, until the task is complete or it needs human input.

---

# Where It Fits in DevOps

Agentic AI is showing up across the DevOps lifecycle:

- **Incident response** — summarise alerts, correlate logs, suggest likely root causes.
- **Code & config** — draft Dockerfiles, pipelines, and Terraform, then explain them.
- **Operations** — triage tickets, generate runbooks, answer "why is this failing?"
- **Review** — flag risky changes and security issues in pull requests.

<Warning title="Agents need guardrails">
An agent that can *act* can also act wrongly. Production systems require guardrails: least-privilege access, human approval for risky actions, and full audit logs. Never give an agent unrestricted power over live infrastructure.
</Warning>

# See the Idea in Code

At its core, an agent loop is simple. This pseudocode captures the shape:

<CommandBlock command={`goal = "Find why the checkout service is erroring"
while not done:
    thought = llm.reason(goal, history)      # decide next step
    action  = thought.tool_call              # e.g. read_logs("checkout")
    result  = run_tool(action)               # execute it
    history.append(result)                   # observe
    done    = llm.is_goal_met(goal, history) # check progress`} language="python" />

The LLM provides the reasoning; the **tools** give it the ability to actually inspect and change the world.

# 💼 Interview Preparation

<InterviewPrep question="How could agentic AI help a DevOps team, and what are the risks?">
  **Benefits:**

  - **Faster incident response** — agents correlate logs and metrics and propose root causes in seconds.
  - **Reduced toil** — automate repetitive triage, runbook execution, and boilerplate config.
  - **Knowledge access** — turn scattered docs and dashboards into answers on demand.

  **Risks and mitigations:**

  - **Wrong actions** — enforce least privilege and require human approval for anything destructive.
  - **Hallucination** — ground the agent in real data via tools; verify before acting.
  - **Security** — audit every action, and never expose secrets to the model unnecessarily.

  The winning approach keeps a human in the loop for high-risk steps while letting the agent handle the safe, repetitive work.
</InterviewPrep>
