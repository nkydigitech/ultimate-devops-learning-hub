# High-Value Use Cases

Agents work best on tasks that are repetitive, data-heavy, or need fast correlation across sources:

| Area | What an agent can do |
|------|----------------------|
| **Incident response** | Correlate alerts, logs, and metrics; propose a root cause |
| **Log analysis** | Summarise thousands of lines into the few that matter |
| **PR review** | Flag risky changes, missing tests, security issues |
| **Runbook automation** | Execute documented, approved recovery steps |
| **Infrastructure drafts** | Generate Dockerfiles, pipelines, Terraform — for human review |
| **On-call assist** | Answer "what changed?" and "what's failing?" instantly |

<Tip title="Start where mistakes are cheap">
Begin with read-only, advisory tasks (summarising logs, suggesting fixes). They deliver value immediately with almost no risk, and build trust before you let an agent take any action.
</Tip>

# The Human-in-the-Loop Pattern

The safest and most common production pattern: the agent does the analysis and *proposes* an action; a human approves before anything changes.

<CommandBlock command={`Agent: detects issue → gathers evidence → proposes fix
Human: reviews proposal → approves or rejects
Agent: executes ONLY approved actions → reports result`} language="text" />

This captures most of the speed benefit (the agent does the tedious investigation) while a human owns every consequential decision.

---

# Guardrails for Production

<Warning title="An acting agent is a privileged user — treat it like one">
Any agent that can change infrastructure has the same blast radius as a human with those permissions. Apply the same discipline: least privilege, approvals, and audit.
</Warning>

The essential guardrails:

- **Least privilege** — give the agent only the permissions its tasks require, nothing more.
- **Read vs write separation** — investigation tools run freely; state-changing tools require approval.
- **Human approval gates** — destructive or production-facing actions always wait for a human.
- **Full audit logging** — record every tool call and decision for review.
- **Scoped secrets** — never expose credentials to the model; keep them behind tools.
- **Rollback ready** — ensure any action the agent takes can be reversed.

# Starting Small

A sensible adoption path:

1. **Advisory only** — the agent summarises and suggests; humans do everything.
2. **Assisted actions** — the agent proposes, humans approve each action.
3. **Bounded autonomy** — the agent auto-handles well-understood, low-risk, reversible tasks; everything else still needs approval.

<Tip title="Trust is earned incrementally">
Expand an agent's autonomy only as it proves reliable on a given task, and only for actions that are low-risk and reversible. There's no rush — the advisory stage alone often saves significant time.
</Tip>

# 💼 Interview Preparation

<InterviewPrep question="How would you responsibly introduce an AI agent into a DevOps workflow?">
  A measured, safety-first rollout:

  1. **Pick a low-risk, high-value use case** — log summarisation or incident triage, read-only to start.
  2. **Ground it in real data** through well-defined tools; never let it guess about your systems.
  3. **Keep humans in the loop** — the agent proposes, a human approves any change.
  4. **Enforce guardrails** — least privilege, read/write separation, approval gates, full audit logs, scoped secrets.
  5. **Ensure reversibility** — only allow actions you can roll back.
  6. **Expand autonomy gradually** — grant more independence only for proven, low-risk, reversible tasks.

  The theme throughout: let the agent absorb the toil and investigation, while humans retain control over consequences.
</InterviewPrep>
