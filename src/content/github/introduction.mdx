# What is Version Control?

Version control is a system that records changes to your files over time, so you can:

- Go back to any previous version
- See who changed what, and when
- Work on the same project with a whole team — without overwriting each other

Without it, teams end up with folders like `project_final_v2_REALLY_final.zip`. Git ends that chaos.

---

# Git vs GitHub — What's the Difference?

| | **Git** | **GitHub** |
|---|---------|-----------|
| What it is | A tool that runs on your machine | A website / cloud service |
| Job | Tracks changes locally | Hosts your Git repositories online |
| Works offline? | Yes | No (it's a remote) |
| Analogy | The camera taking snapshots | The photo album you share with others |

<Tip title="The one-line version">
**Git** is the version-control tool. **GitHub** is a place to store and share Git repositories in the cloud (alternatives include GitLab and Bitbucket).
</Tip>

# The Core Git Workflow

Almost everything in Git follows this cycle:

<CommandBlock command={`Working Directory   →   Staging Area   →   Repository   →   GitHub
   (edit files)         (git add)        (git commit)     (git push)`} language="text" />

You edit files, **stage** the changes you want to keep, **commit** them as a snapshot, and **push** them to GitHub to share.

# Install & Configure Git

<CommandBlock command={`sudo apt update && sudo apt install git -y   # Ubuntu / WSL
git --version                                # verify`} />

Set your identity once — every commit you make is stamped with it:

<CommandBlock command={`git config --global user.name "Your Name"
git config --global user.email "you@example.com"`} />

<Terminal
  command="git --version && git config --global user.name"
  output={`git version 2.43.0
Your Name`}
/>

# 💼 Interview Preparation

<InterviewPrep question="Why do DevOps teams consider Git essential?">
  Git is foundational to DevOps for several reasons:

  - **Single source of truth:** all code and often infrastructure definitions live in Git.
  - **Collaboration:** branches and pull requests let many engineers work in parallel safely.
  - **Traceability:** every change is attributed and reversible, which is critical for audits and incident response.
  - **Automation trigger:** CI/CD pipelines (like GitHub Actions) are triggered by Git events such as a push or a merged pull request.

  In modern practice, "GitOps" even uses Git as the desired-state source for deploying infrastructure.
</InterviewPrep>
