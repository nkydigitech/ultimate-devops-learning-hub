# Collections: Lists and Dictionaries

These two structures carry most DevOps data (servers, configs, API responses).

**A list** — an ordered sequence:

<CommandBlock command={`servers = ["web-01", "web-02", "db-01"]

print(servers[0])        # web-01
print(len(servers))      # 3
servers.append("web-03") # add one`} language="python" />

**A dictionary** — key/value pairs (just like JSON):

<CommandBlock command={`server = {
    "name": "web-01",
    "cpu": 4,
    "region": "eu-west-1",
}

print(server["region"])   # eu-west-1`} language="python" />

<Tip title="Dictionaries = JSON">
API responses and config files are almost always key/value data. Python dictionaries map onto JSON directly, which is why they show up constantly in DevOps scripts.
</Tip>

# Making Decisions: if / elif / else

<CommandBlock command={`load = 0.85

if load > 0.9:
    print("CRITICAL: scale up now")
elif load > 0.7:
    print("WARNING: load is high")
else:
    print("OK")`} language="python" />

<Warning title="Indentation is the syntax">
Python has no braces — **indentation defines blocks**. Use 4 spaces consistently. Mixing tabs and spaces is the classic beginner error and will raise an `IndentationError`.
</Warning>

# Loops

**Loop over a list** with `for`:

<CommandBlock command={`servers = ["web-01", "web-02", "db-01"]

for server in servers:
    print(f"Checking {server}...")`} language="python" />

<Terminal
  command="python3 loop.py"
  output={`Checking web-01...
Checking web-02...
Checking db-01...`}
/>

**Repeat while a condition holds** with `while`:

<CommandBlock command={`attempts = 0
while attempts < 3:
    print(f"Retry {attempts + 1}")
    attempts += 1`} language="python" />

<Tip title="f-strings">
`f"Checking {server}"` is an f-string — it drops variables straight into text. It's the cleanest way to build log lines and messages, and you'll use it everywhere.
</Tip>

# 💼 Interview Preparation

<InterviewPrep question="What's the difference between a list and a dictionary, and when would you use each?">
  Both are core Python collections but serve different purposes:

  - **List** — an *ordered* sequence accessed by numeric index (`servers[0]`). Use it when order matters or you just have a collection of similar items to iterate over (a list of hostnames, a list of log lines).
  - **Dictionary** — *key/value* pairs accessed by key (`server["region"]`). Use it when each item has named attributes, or to model structured data like a JSON API response or a config object.

  In practice you often combine them — for example a **list of dictionaries** to represent many servers, each with its own name/cpu/region. That structure is exactly what you get back from most cloud APIs.
</InterviewPrep>
