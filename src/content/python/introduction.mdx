# Why Python for DevOps?

You already know Bash from the Linux section. Bash is perfect for short command sequences, but it gets messy fast for anything with logic, data, or APIs. Python shines exactly there:

| Task | Bash | Python |
|------|------|--------|
| Chain a few commands | ✅ Great | Overkill |
| Parse JSON from an API | 😖 Painful | ✅ Built-in |
| Loops with real data structures | 😖 Clunky | ✅ Clean |
| Call AWS/Azure APIs | ❌ | ✅ (SDKs) |
| Readable by the whole team | ⚠️ | ✅ |

<Tip title="Bash and Python are teammates, not rivals">
A good DevOps engineer uses Bash for quick glue and Python when there's real logic or data involved. Knowing when to switch is a skill in itself.
</Tip>

# Install Python

Most Linux systems and macOS already ship with Python 3. Check first:

<CommandBlock command={`python3 --version
pip3 --version`} />

<Terminal
  command="python3 --version"
  output="Python 3.12.3"
/>

If it's missing on Ubuntu/WSL:

<CommandBlock command={`sudo apt update && sudo apt install -y python3 python3-pip`} />

<Warning title="Use python3, not python">
On many systems `python` still points to old Python 2 (or nothing at all). Always use `python3` and `pip3` to be safe.
</Warning>

---

# Two Ways to Run Python

**1. The interactive shell (REPL)** — great for quick experiments:

<Terminal
  command="python3"
  output={`>>> 2 + 2
4
>>> print("Hello, DevOps")
Hello, DevOps
>>> exit()`}
/>

**2. A script file** — how real automation lives. Create `hello.py`:

<CommandBlock command={`print("Hello, DevOps!")
print("Python is running from a file.")`} language="python" />

Then run it:

<Terminal
  command="python3 hello.py"
  output={`Hello, DevOps!
Python is running from a file.`}
/>

# 💼 Interview Preparation

<InterviewPrep question="When would you choose Python over a shell script for automation?">
  A strong answer shows judgement rather than dogma:

  - **Use a shell script** for short, linear sequences of existing CLI commands — deploy steps, quick file operations, cron one-liners.
  - **Reach for Python** when the task involves real logic (conditionals, loops over structured data), parsing formats like JSON/YAML, calling REST APIs or cloud SDKs, error handling, or code that other engineers must maintain.

  I also consider **maintainability**: once a Bash script grows past ~50 lines or needs functions and data structures, Python is usually clearer and easier for a team to work on. The goal is the right tool for the job, not using one language for everything.
</InterviewPrep>
